# 発想の補助資料

問題の構造から出した仮説を広げ、実現手段へつなげるための資料。症状に関係する節だけ読む。名称は別名・略称を同じ項目へまとめている。標準アルゴリズム、表現の工夫、発想法、実験手法を含む。各項目は候補であり、効果は対象問題で確かめる。

## 症状から読む

観測だけで原因は確定しない。次は確認の入口として使い、合わない症状へ無理に当てはめない。

| 共有された症状・疑問 | 原因の候補 | 参照先と判別の入口 |
|---|---|---|
| 何を試しても似た解になる | 表現で解の形を固定／探索が同じ場所へ集中 | 「表現と自由度」「構築・探索器・近傍」。今の表現で、手作りの別形状を表せるか。 |
| 現在得点の高い手が終盤に詰まる | 決定が早すぎる／将来価値の評価不足 | 「決定順序」「探索と計算」。残る合法手・必須資源・待ちの増え方を見る。 |
| 上位状態は良いのに出力の得点が伸びない | 代理評価のずれ／復元で損失 | 「部分問題」「採用された案の実験」。復元前後で何を失うか、同じ上位状態の別復元で変わるか。 |
| 初期解や近傍を変えると結果が大きく振れる | 複数の解の系統／移れない構造間の壁 | 「構築・探索器・近傍」。良い解同士の差が順序・所属・骨格のどこにあるか。 |
| 評価が重く候補をほとんど試せない | 冗長な状態／大きい再計算範囲 | 「高速化」。一変更の影響範囲と、詳細を後回しにできるかを見る。 |
| 平均は良いが特定の入力で崩れる | 固定した前提の適用限界／別の損失要因 | 「推定・確率・対戦・学習」「採用された案の実験」。入力の特徴と失敗構造を対応させる。 |
| 改善余地がどこにあるか分からない | 損失の内訳・理想値が不明 | 「探索と計算」「部分問題」。制約を一つ緩めた理想状態で、何の費用が支配的か見積もる。 |

## 表現と自由度を変える

「何を状態にするか → 必要な操作 → 安く扱う表現」の順に具体化する。問題文の出力形式や現在のデータ構造に縛られない。

| 発想・関連名 | 問いと具体化 | 成立条件・最初の確認 |
|---|---|---|
| 解の座標系、表現反転（representation inversion） | 木を高さ、形を境界、経路を訪問順のように別変数で生成できるか。 | 小例で合法な出力へ復元する。近い座標が近い得点・安い編集を生むか。 |
| 意味射影、十分状態圧縮（sufficient-state compression） | 後から復元できる細部や不要な履歴を落とせるか。 | 同じ状態へまとめた履歴の合法手と将来価値が同じか。近似なら失う情報を明示する。 |
| 集合効果、活動集合（active set） | 構築手順より被覆・到達・競合集合、または参加する要素だけが本質か。 | 集合が同じでも、資源・時刻・接続などが違って未来が変わらないか。 |
| 同値類化、対称性の商空間化（symmetry quotient） | 名前・回転・反転・平行移動だけ違う状態を一つにできるか。 | 制約・得点・将来の遷移も保存される範囲を調べる。 |
| 基底表現、探索空間の制限 | 少数の方向・部品・規則で、強く探索できる解の一群を作れるか。 | 捨てる自由度による損失と、増える候補数・深さを比べる。 |
| 割当分離、クラスタ化、粒度変更 | 位置・担当・量、個体・群・階層を分けると何が小さくなるか。 | 群間の相互作用と、群を作り直す必要を確認する。 |
| 補集合を解く | 選ぶ対象より、除く対象・穴・未充足の方が少ないか。 | 補集合から目的値・制約・出力を簡単に復元できるか。 |
| 骨格＋残差、差分・残差表現 | 良い大構造を保ち、未解決部分や変更だけを持てるか。 | 残差を直すために骨格を変える必要がある場合も、変更手段を残す。 |
| 持続リンク（persistence） | 各時点の配置より、時点間で何を再利用するかを変数にできるか。 | 同じ資源・境界・接続を維持する利益と、維持による自由度の損失を比べる。 |
| パッキング表現、領域所有、境界探索 | 座標全体を持たず、隙間・接触・所有者・境界を主変数にできるか。 | 内部が自動で決まるか。境界変更で連結性・容量などを保てるか。 |
| 直積状態探索（product-state search） | 位置だけでは不十分なら、姿勢・資源・小さな内部状態を組み合わせるか。 | 必要な依存だけ加え、状態数と重複除去の条件を見積もる。 |
| コストの見直し | 幾何距離より、状態の編集量・ハミング距離・追加固定費が目的に近いか。 | 安いと見なす変更が実際の得点・実行コストでも安いか確認する。 |

## 決定順序と構築を変える

| 発想・関連名 | 問いと具体化 | 成立条件・最初の確認 |
|---|---|---|
| 遅延決定（delayed commitment） | 向き・担当・詳細を、情報が増えるまで保留できるか。 | 保留した選択肢を表現でき、後で合法に完成できるか。 |
| 過去改変（retroactive modification）、反実仮想再生 | 後続を見て過去の一判断を差し替えられるか。 | どこまで巻き戻し、何を再生すれば整合するか。 |
| 将来予約、選択肢価値、後悔値 | 今の利益が将来の必須資源・余白を潰していないか。 | 残る合法手や後回しにする損失を、現在利益と比較できるか。 |
| 制約優先構築、解放順序（unlock-first） | 詰まりやすい要素、または後続の行動集合を増やす仕事から処理するか。 | 優先した仕事が何の制約を解消するかを示す。 |
| 目標状態先行、目標側固定（goal anchoring） | 良い完成形を先に置き、実現操作を後で求められるか。 | 理想状態への到達費用が利益を打ち消さないか。 |
| 骨格先行（scaffold-first）、便乗・共有限界費用 | 既に払う経路・設備・操作の固定費へ別需要を載せられるか。 | 単独費用より追加費用で挿入を評価する。容量・混雑の増分も含める。 |
| 代理世界、緩和して射影（relax-and-project） | 制約を緩めた世界で骨格を得て、元問題へ修復できるか。 | 代理評価から元の得点までの損失を分ける。 |
| 良い部分の固定、暗黙の前提の解放 | 固定すべき良い構造と、慣習で固定した設計を分けられるか。 | 問題文が要求していない全順序・直交性・担当分担などを見直す。 |
| 模様・モチーフ、部品設計、階層統合 | 反復形を抽出するか、安く作れて修復しやすい部品を自分で設計するか。 | 部品作成・配置・残差修復の総費用で比較する。 |
| 不可逆決定管理（irreversible commitment） | 今の配置・結合が失わせる自由度は何か。 | 後から戻せる部分と戻せない部分を分け、不可逆な判断を遅らせる。 |
| 上書き逆算（reverse overwrite construction） | 最後の書込みが最終値を決めるなら、後ろから計画できるか。 | 後の操作で消える差を許し、確定済みの領域だけ保護できるか。 |
| 自己適用による増幅（recursive amplification） | 生成物を次のコピー・結合の材料として使えるか。 | 操作の適用範囲・重複・コストを仕様で確認する。 |

## 探索と計算を変える

| 発想・関連名 | 問いと具体化 | 成立条件・最初の確認 |
|---|---|---|
| 代理目的関数、二段評価 | 安い指標で候補を絞り、少数を本評価できるか。 | 代理評価が本当に良い候補を落とす条件と、復元後の順位のずれを見る。 |
| ポテンシャル・理論目標 | 今の得点に現れない進捗や、理想状態との差を測れるか。 | 補助指標を良くすると元の目的も良くなる筋道を示す。 |
| ボトルネック評価 | 総和に隠れる詰まり・最悪要素が全体を支配していないか。 | 平均と最悪の改善が競合するか、得点式へ戻って考える。 |
| 楽観上界・安全下界（optimistic/pessimistic bound） | 制約を緩めて改善余地や早期棄却を判断できるか。 | 保証された境界と経験的な見積もりを区別する。 |
| 粗密切替、複数尺度、段階切替 | 大構造と細部、序盤と終盤を同じ精度・評価・近傍で扱う必要があるか。 | 粗い段階で捨てた良い構造を後で回復できるか。 |
| 依存関係状態、因果修復 | 全順序を因果関係の半順序へ変え、影響した決定だけ再生できるか。 | 依存を取りこぼさず、再生範囲が小さくなるか。 |
| 再利用語彙、効果コンパイル | 頻出操作列を一手にし、その効果を前計算できるか。 | 語彙の変更時の再計算費用と、再利用できる回数を比べる。 |
| 無効状態の探索、一時違反と修復 | 可行解だけの近傍で、別の良い構造へ届かなくなっていないか。 | 違反量の評価と可行解へ戻す方法を先に用意する。 |

## 発想をつなぐ

複数技法は、前の変更が次を可能にする関係を説明してつなぐ。以下は具体化の例であり、対象問題で成立するとは限らない。

| 最初の変更 → 可能になること | 小さな確認と、崩れやすい前提 |
|---|---|
| 訪問順を固定 → 運ぶ量だけ最小費用流 → 外側は順序だけ探索 | 保存則・容量・費用がフローで表せるか。内側を解く時間まで含める。 |
| 部品と開始状態を決める → 被覆集合を計算 → 部品配置を集合被覆として選ぶ | 部品間の衝突や順序依存が、集合の和だけでは扱えない可能性。 |
| 接続の骨格を先に作る → 固定費を共有 → 追加費用で需要を挿入 | 混雑・容量・維持費を無視すると、便乗利益を過大評価する。 |
| 少数の座標から出力を復元 → 状態を小さくする → 多様な部分解をビームに残す | 復元不能な状態や、似た完成形しか作れない制限を確認する。 |
| 操作をマクロにする → 小状態への効果を遷移表にする → マクロの順序・再利用を探索 | 外部環境への依存が強いと、前計算表を使い回せない。 |
| 変更の依存関係を持つ → 関連部分をまとめて壊す → 局所DP等で修復する | 大きな破壊がいつも同じ解へ戻るなら、修復の自由度も見直す。 |

変数・一手・復元、または安い反証方法が明確になったら一案としてまとめる。完成した複合解法でなく、最初の変換だけが有望な段階でもヒントにしてよい。

## 部分問題をアルゴリズムへ結び付ける

何を固定すると条件が成立するかを示す。厳密法の保証は切り出した部分問題に限られる。

| 問い・状況 | 候補・別名 | 条件・最初の確認 |
|---|---|---|
| 少数の変数だけ未確定か | 全探索、分枝限定法（branch-and-bound）、厳密小問題修復 | 候補数が収まるか。枝刈りには正しい境界が必要。 |
| 履歴を小さな十分状態にできるか | 動的計画法（DP）、メモ化探索 | 状態・遷移・目的を定義し、同じ状態の未来が一致するか。 |
| 短区間や小集合だけ最適化するか | 区間再最適化、窓内DP、区間DP、部分集合DP | 窓内DPと区間分割のDPを区別し、外部との境界条件を含める。 |
| 前後を別々に扱えるか | 逆向き探索、双方向探索、半分全列挙（meet-in-the-middle） | 逆遷移や中間での照合条件を定める。前後を独立に列挙できるか。 |
| 移動や修復が状態遷移か | BFS、0-1 BFS、Dijkstra、最短路木、BFS修復 | 等コスト・辺重み0/1・非負重みを使い分ける。姿勢・資源等も必要なら状態へ入れる。 |
| 目標までの下界を作れるか | A* | 最短性が必要なら過大評価しない見積もりと適切な再探索処理を使う。 |
| 一対一の対応を決めるか | 二部マッチング（matching）、Hungarian法、マッチング修復 | 対応の可否・費用で表せるか。割当同士の干渉が別に残らないか。 |
| 保存される量を配分するか | 最大流（max-flow）、最小費用流（min-cost-flow）、フロー修復 | 容量・保存則・辺ごとの費用で表せるか。外側の経路や順序を固定する。 |
| 二分割を境界費用で決めるか | 最小カット（min-cut）、カット・分離点化 | 全ての目的・制約がカット容量で表現できるとは限らない。分離後の独立性を確認する。 |
| 選んだ点を安く接続するか | MST（Kruskal法、Prim法）、木・骨格化、Steiner木の近似構築 | 必須頂点だけの木か、追加頂点を許すか、容量等があるかを区別する。 |
| 順序を決めれば出力が作れるか | 巡回路化・TSP化、順列探索 | 移動費が訪問順から決まるか。状態遷移や作業の相互作用が残るか。 |
| 一選択で複数需要を満たすか | 集合被覆（set cover）、最大被覆、貪欲被覆 | 未被覆への追加寄与と費用を比べる。相互作用を集合の和で扱えるか。 |
| 変数を分けると片側が簡単か | 交互最適化（alternate optimization）、座標降下、厳密完成 | 固定する軸を反転する。局所解への固定化と内側の計算量も見る。 |
| 資源競合を価格で分離するか | 双対視点、ラグランジュ緩和、混雑価格、劣勾配更新 | 分離した問題の解を、最後に元の容量・制約へ戻せるか。 |
| 小問題から良い構造を知りたいか | 制約プログラミング（CP）、CP-SAT、重み付き制約充足問題（WCSP） | 利用可能な環境と問題規模で成立する場合に、部分問題や比較用の基準へ使う。 |

## 構築・探索器・近傍を選ぶ

探索器より先に状態・合法な遷移・評価・復元を定める。DP・SA・Beam等の実装は対象リポジトリの相談・許可ルールに従う。

| 問い・状況 | 候補・別名 | 条件・最初の確認 |
|---|---|---|
| 素直な初手を作るか | 貪欲法、制約優先、後悔値付き貪欲 | 現在利益・残る合法手・後回しによる損失を比べる。 |
| 初期構築の決め打ちを減らすか | 乱択貪欲、多点開始＋優良解保持、GRASP | GRASPでは乱択構築と局所改善を組み合わせる。初期性能と改善後を分けて見る。 |
| 早期判断の価値が後で分かるか | ビームサーチ（Beam search）、多様性ビーム | 将来評価と重複判定を定め、同じ構造の候補だけに偏らないか確認する。 |
| 改善手を積めるか | 山登り（hill climbing）、最良改善・最初改善 | 近傍の改善量と評価コストを確認し、単純な比較基準にする。 |
| 悪化を経由して移る必要があるか | 焼きなまし（SA）、再加熱、しきい値受理 | 得点差の尺度と受理則を対応させる。表現上移れない構造は温度だけでは解決しない。 |
| 良い記録の周辺を広く歩くか | Record-to-record travel（RRT） | 現在解ではなく最良記録からの許容差を基準にする受理法。SA・しきい値受理と区別する。 |
| 同じ変更を往復するか | タブー探索（tabu search） | 変更・属性の短期禁止で周期を避け、必要な改善手を遮りすぎないか見る。 |
| 局所最適から別の谷へ移るか | 反復局所探索（ILS）、kick、再スタート、多点探索 | 摂動の単位・初期条件を変え、いつも同じ構造へ戻っていないか見る。 |
| 順序や接続の局所が悪いか | 交換（swap）、挿入（insert/relocate）、区間移動・反転、2-opt、k-opt | 非対称費用・順序制約では内部の費用変化や修復も含める。 |
| 所属・領域の粒度が悪いか | 分割・統合（split/merge）、境界移動、押し出し連鎖（ejection chain） | 容量等が単独変更を妨げるなら、関連要素を連鎖して動かす。 |
| 単独変更が全て悪化するか | 複合近傍（compound move）、束・パケット修復 | 同時に変える必要がある因果・相互作用を特定する。 |
| 小近傍で骨格が固定されるか | 大規模近傍探索（LNS）、悪い部分・関連部分・ランダム部分の破壊 | 何を壊し、貪欲・DP・BFS・matching・flow等でどう埋めるかをセットで示す。 |
| 可行解だけでは移れないか | 制約修復、ペナルティ法、一時違反 | 違反量と復帰方法を定め、最終的に可行解を取り出す。 |
| 良い解の異なる部分を使えるか | 優良解プール（elite pool）、path relinking、部分構造の交叉 | 共通部分を保って差分を置換し、組合せ時の合法性と多様性を見る。 |
| 近傍ごとの効き方が違うか | 適応的近傍混合（adaptive neighborhood mix） | 改善量だけでなく時間当たりの寄与と、探索段階による違いを見る。 |
| 解の系統を複数保ちたいか | 島モデル探索（island search） | 異なる探索群を保ち、優良解の交換で全群が同じ構造に潰れないか。 |
| 一手の生成が難しいか | 探索内ビーム、Beam-inside-SA、厳密小問題修復 | 内側へ使う時間と、外側の反復が減る影響を比べる。 |
| 弱い候補へ同じ予算を使う必要があるか | 予算階段（budget ladder）、段階的選抜 | 少ない予算で候補を絞れるか。立ち上がりが遅い良案を落とす可能性を見る。 |

## 複数主体・時間・制御

| 問い・状況 | 候補・別名 | 条件・最初の確認 |
|---|---|---|
| 同時最適化を順次計画へ分けるか | 優先順位付き計画、時空間探索、予約表 | セル占有だけでなく辺のすれ違い等も扱い、優先順依存を見る。 |
| 衝突した主体だけ分岐するか | 衝突分割探索（Conflict-Based Search、CBS） | 衝突を禁止制約として分けられるか。分岐数と個別経路探索の負荷を見積もる。 |
| 担当・領域で干渉を減らすか | 役割分担、Voronoi所有、soft ownership、混雑価格 | 固定分担と一時的な越境を比べ、需要偏りや競合資源を確認する。 |
| 遠い未来を固定しすぎているか | 移動窓計画（rolling horizon）、モデル予測制御（MPC） | 窓の外の詰まりを終端評価・予約で補えるか。 |
| 何も起きない時間が長いか | イベント駆動状態・シミュレーション | 変化点間を飛ばしても、途中の制約・得点を正しく扱えるか。 |
| 長い操作列を規則へ圧縮するか | 方策表現、有限状態制御器・機械（FSM）、マクロ・命令語彙設計 | 必要な履歴を少数内部状態に持てるか。規則の反復が多様な場面でも使えるか。 |
| 実演や複数主体から共通制御を得るか | 実演から制御器化、共有制御分解、協調マクロ | 共通規則と個別補正を分け、圧縮による損失と協調の利益を比べる。 |

## 推定・確率・対戦・学習

隠れ状態・確率・相手・事前計算などが問題に存在するときに使う。学習・調整の開発時間と、本番で使える実行時間を分ける。

| 問い・状況 | 候補・別名 | 条件・最初の確認 |
|---|---|---|
| 一点推定で足りるか | 最尤推定（MLE）、事後最大推定（MAP） | 観測モデル・事前分布を明示し、誤差が後続の判断を変えるか見る。 |
| 複数の世界が観測と整合するか | ベイズ推定、仮説集合・オンライン推定、粒子フィルタ、MCMC | 尤度を更新し、真の世界の脱落や少数仮説への早い集中を確認する。 |
| 近い入力の未知量が相関するか | ガウス過程（GP）、ガウス過程回帰 | 表現・カーネルと相関の仮定が合うか。更新・予測の計算量も見積もる。 |
| 情報を得る行動に価値があるか | 能動観測・情報利得、情報価値（VOI）、推定と最適化の同時化 | 不確実性が減るだけでなく、その情報が後続の選択を変えるかを観測費用と比べる。 |
| 未知の未来をサンプルで比較するか | 事後分布・シナリオ標本化、Thompson sampling、モンテカルロ展開・補完 | 候補を同じシナリオで比較できるなら揃える。標本ばらつきと一点予測への依存を見る。 |
| 小状態なら分布を直接進めるか | 確率・期待値伝播、期待値DP | 分布更新のコストと、期待値だけで落とす依存関係を確認する。 |
| 低得点側のリスクが重要か | リスク考慮目的、ロバスト最適化 | 得点式・評価目的に沿って平均とのトレードオフを示す。 |
| 試行回数を適応配分するか | バンディット、UCB、適応的シミュレーション配分 | 有望さと不確実性で配分する。少数試行の偶然で良い候補を捨てないか。 |
| 相手が応答するか | 相手モデル、最良応答、minimax、戦略集団、搾取可能性の確認 | 特定相手への過適合と、自分を崩す応答を調べる。 |
| 入力の型で得意解法が変わるか | 入力条件付き戦略、解法ポートフォリオ | 特徴と戦略の対応を確かめ、調整用と評価用の入力を分ける。 |
| 高価な評価をモデルで節約するか | 代理モデル、ベイズ最適化、expected improvement、UCB、TPE | 意味のあるパラメータ空間・予測誤差・評価費用があるか。モデルの費用も含める。 |
| 長い開発時間を事前学習に使うか | オフライン方策・価値学習、NN、蒸留、実演から規則を抽出 | 規則・環境が許す場合に、実行時の速度と精度を比較する。学習した構造が別入力にも通じるか。 |
| 小さい予算で候補の良否を知るか | 多忠実度調整（multi-fidelity tuning）、予算階段 | 小入力・短時間での順位が、本条件で逆転しないかを確認する。 |

## 高速化を探索へつなげる

高速化で増やせる候補数、探索深度、使える部分問題を示す。実行結果からの改良は、メインSkillの実行後の境界に従う。

| 必要な操作 | 表現・技法候補 | 条件・最初の確認 |
|---|---|---|
| 集合の交差・和・差・個数 | bitset、ビット盤面・マスク、隣接bitset、占有マスク、popcount | 要素数・密度に合うか。疎な集合なら列挙も比較する。 |
| 同値状態の検索 | 正規形符号化、ハッシュ、状態圧縮 | ハッシュだけで厳密な同一性を断定しない。正規化で必要な違いを消さないか。 |
| 所属・木・順序の編集 | ラベル・所有者配列、親・深さ・高さ配列、順列・順序表現 | 一変更で更新する派生情報と、合法性判定の費用を見積もる。 |
| 近傍点・形状候補の検索 | 空間bucket、幾何候補生成、階層クラスタ化 | 候補制限が良い構造を落とさないか。非幾何的な近さも考える。 |
| 同じ小操作の反復 | 前計算、モチーフ・template辞書、遷移表コンパイル、伝達関数 | 時刻・環境・資源への依存と、辞書変更時の再構築費用を確認する。 |
| 列・状態の部分変更 | 差分評価、局所cache、prefix/suffix、チェックポイント再生、依存関係再生 | 合成可能な情報と影響範囲を定め、全評価との一致を確かめる。 |
| 提案の採否・探索木の移動 | 巻き戻し・Undoログ、rollback DSU、二重バッファ、差分ビーム探索、コピー除去 | 派生状態も戻るか。使うデータ構造の操作が巻き戻し可能か。 |
| 変更箇所だけ更新 | 活動集合・dirty集合、局所キャッシュ | 依存を追えているか。局所変更に見えて全域が変わる場合を確認する。 |
| 多数候補を比較 | 候補一括生成、二段評価、遅延評価、早期棄却 | 共通前処理を共有する。厳密な境界による枝刈りと近似的な選別を区別する。 |
| 状態の保存・コピー・走査 | 連続メモリ、固定容量flat表現、整数詰め込み、SIMD | 値の範囲と環境の制約を確認し、ボトルネックとなる操作へ適用する。 |
| 得た時間を探索へ使う | 計測から探索へ（profiling-to-search） | 同じ候補数での高速化と、同じ時間で候補を増やす効果を分ける。 |

## 採用された案の実験

以下は依頼された実験の設計候補。解答プログラムを実行したら結果・観察を報告して止まり、結果に基づく改善にはユーザーの新たな明示的指示を待つ。

| 確かめたいこと | 手法 | 何を区別するか |
|---|---|---|
| 表現が良い解を落としていないか | 探索空間の確認（search-space audit）、小例の手構成 | 表現不能・到達不能と、探索時間が足りない状態。 |
| 上位状態の価値を復元で失うか | 復元器の確認（decoder audit）、復元前後・別復元の比較 | 外側の目的のずれ、内側の復元品質、可行化コスト。 |
| どこまで改善の余地があるか | 小問題の厳密解との比較（oracle calibration）、緩和による境界 | 厳密解との差と、本サイズでも使える構造。小問題の強さをそのまま外挿しない。 |
| 良い結果の原因は何か | アブレーション、共通初期解・固定予算による比較 | 表現・構築・改善器・計算量それぞれの寄与。 |
| どんな入力に効くか | 固定seed群（seed panel）、seed別差分分布、苦手seed探索 | 平均改善、少数の大改善、多数の小悪化、構造的な失敗条件。 |
| 仮説の筋道が正しいか | 構造指標（structural metrics） | 共有固定費、待ち、未充足、修復量、候補多様性など、変更に直結する量。 |
| 状態更新を信頼できるか | 再生検証、差分評価と全評価の比較 | スコアの変化と、実装や計測の不整合。 |
| 長期戦で同じ試行を繰り返していないか | 仮説・試行メモ（hypothesis ledger） | 確認済みの事実、原因の推測、未確認の前提、再試行する条件。 |

まず仮説を判別できる小さな比較を置く。結果に応じた再設計はユーザーの次の指示を受けて行う。

## その他

- **評価入力・環境自体の設計（adversarial instance layer）**：参加者が入力を作る形式なら、自分が処理しやすく相手の前提が崩れる構造を考える。通常の固定入力問題へは持ち込まない。
- **失敗を情報として使う**：失敗が排除する仮説や適用範囲を考える。コンテスト内の観測行動と、開発中の解答プログラム実行を区別し、後者の結果から改良するときはユーザーの新たな指示を待つ。

ここにない発想でも、問題の構造に根拠があれば候補にする。既存の分類は探索の補助として使う。
